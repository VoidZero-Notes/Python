## 数据库的分类

| 分类 | 数据模型 | 特点 | 代表作 |
|---|---|---|---|
| **关系型数据库** | 表（行+列），SQL 操作 | 严格 Schema、强 ACID、支持 JOIN | PostgreSQL、MySQL、Oracle、SQL Server |
| **文档型数据库** | JSON/BSON 文档 | Schema-less、易扩展、适合半结构化数据 | MongoDB、CouchDB、Firebase Firestore |
| **键值型数据库** | Key-Value 对 | 超高读写性能、无查询语言、操作简单 | Redis、DynamoDB、LevelDB、Riak |
| **列族型数据库** | 列族，稀疏矩阵存储 | 适合海量写入、列可扩展、压缩率高 | HBase、Cassandra、Bigtable |
| **图数据库** | 节点+边，图结构 | 擅长深度关联查询、最短路径/推荐 | Neo4j、ArangoDB、TigerGraph |

> 补充说明：键值型、列族型、图数据库统称为 **NoSQL**；文档型也常归入 NoSQL 阵营。关系型数据库则统称为 **SQL** 数据库。

## 什么是 SQL

SQL（Structured Query Language，结构化查询语言）是操作关系型数据库的标准语言。无论使用 PostgreSQL、MySQL 还是 Oracle，SQL 的语法都高度通用。

SQL 主要做两件事：

1. **告诉数据库做什么**（而非怎么做）—— SQL 是声明式语言
2. **操作数据**—— 增、删、改、查

## SQL 的细分

| 分类 | 全称 | 作用 | 常见关键字 |
|------|------|------|-----------|
| **DDL** | Data Definition Language | **数据定义**，操作数据库和表结构 | `CREATE`、`ALTER`、`DROP`、`TRUNCATE` |
| **DML** | Data Manipulation Language | **数据操作**，对表数据进行增删改查 | `INSERT`、`SELECT`、`UPDATE`、`DELETE` |
| **DCL** | Data Control Language | **数据控制**，管理用户和权限 | `GRANT`、`REVOKE` |
| **TCL** | Transaction Control Language | **事务控制**，管理事务 | `BEGIN`、`COMMIT`、`ROLLBACK`、`SAVEPOINT` |

> 要操作数据，先得有存放数据的结构。所以学习顺序是 **DDL → DML**，先建表，再操作数据。

## 数据库设计三范式

| 范式 | 核心要求 | 通俗理解 | 反例 |
|---|---|---|---|
| **第一范式（1NF）** | 列不可再分，每列都是原子值 | 一个格子只存一个值，不存数组或复合数据 | 一行里存多个联系电话（`138xxx, 139xxx`） |
| **第二范式（2NF）** | 满足 1NF + 非主键列完全依赖于主键（消除部分依赖） | 复合主键时，每一列都要依赖整个主键，不能只依赖其中一部分 | `订单明细表` 主键是 `(订单ID, 商品ID)`，但 `商品名称` 只依赖 `商品ID` |
| **第三范式（3NF）** | 满足 2NF + 非主键列之间不能有传递依赖 | 非主键列不能依赖于另一个非主键列 | `学生表` 有 `院系ID` 和 `院系名称`，后者依赖于前者，应拆分出院系表 |
