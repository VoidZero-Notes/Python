优化当前指定的 Python 技术笔记 Markdown：补齐 JavaScript 类比，并统一为已优化笔记的体例。

## 输入

- 用户会 `@` 一个或多个待优化的 `.md` 文件
- 若未指定文件，先问清要优化哪几个，禁止瞎猜

## 风格锚点（必须先读）

在同目录（或同级已优化笔记）中，任选 **1～2 个已优化样本** 作为体例标准，优先：

- `Python语言核心/2. 基本语法.md`
- `Python语言核心/3. 容器类型.md`
- `Python语言核心/4. 函数.md`
- `Python语言核心/5. 作用域.md`

以这些文件的实际写法为准，不要另发明体例。

## 必须完成的改造

1. **文首对照表**  
   若该主题适合总览，在开头补 `| Python | JavaScript 对应 |` 表（或给已有总览表加 JS 列）。无对应时写「无直接对应」并给常见替代写法。

2. **JavaScript 类比**  
   每个重要的 Python 示例代码块后，跟：

   ```text
   JavaScript 类比：

   ```js
   // ...
   ```
   ```

   要求：
   - 语义对齐，不是逐字翻译
   - 优先箭头函数 / `const`；输出用 `console.log`
   - Python 独有概念用 `**JavaScript 无直接对应。**` + 一句替代方案
   - 需要补充差异时用简短引用块 `> **说明：** ...`
   - 作业题保持 Python，不要为作业补 JS 类比

3. **缩进统一为 2 空格**  
   所有 `python` / `js` 代码块内缩进改为 2 空格；删除 Tab；不要混用 4 空格。

4. **结构体例**  
   - 章节之间不要用单独的 `---` 分隔线（与已优化样本一致）
   - 保留原有章节逻辑与作业；可修正明显笔误（如「返回两个字典」实为返回函数）
   - 不删减教学内容，不借机大改大纲

5. **直接改文件**  
   原地更新目标 `.md`，不要只输出 Diff 而不写入。

## 自检

写完后快速确认：

- [ ] 无 `\t`
- [ ] 代码缩进为 2 空格
- [ ] 主要示例都有 JS 类比（作业除外）
- [ ] 文首有 Python/JS 对照（或说明为何不需要）
- [ ] 体例与锚点样本一致

完成后用一两句话说明改了哪些文件、做了哪些类改造即可。
