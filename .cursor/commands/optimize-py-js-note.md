优化当前指定的 Python 技术笔记 Markdown：补齐前端/运行时侧类比，并统一为已优化笔记的体例。

## 输入

- 用户会 `@` 一个或多个待优化的 `.md` 文件
- 若未指定文件，先问清要优化哪几个，禁止瞎猜

## 风格锚点（必须先读）

在同目录（或同级已优化笔记）中，任选 **1～2 个已优化样本** 作为体例标准，优先：

- `Python语言核心/2. 基本语法.md`
- `Python语言核心/3. 容器类型.md`
- `Python语言核心/4. 函数.md`
- `Python语言核心/5. 作用域.md`

以这些文件的实际写法为准，不要另发明体例。

## 类比选型（强制）

每个概念 / 示例只从下面三者中选 **一个最合适** 的对照侧，不要三者并列、不要拼凑：

| 候选 | 何时优先选 |
| ---- | ---------- |
| **TypeScript** | 有类型系统、装饰器、`interface`/`enum`、泛型等更贴近的对应 |
| **JavaScript** | 语言层面的通用语义（作用域、闭包、原型、普通函数/对象） |
| **Node.js** | 模块系统、文件系统、进程、包管理、运行时 API（`fs`/`path`/`Buffer` 等） |

规则：

- **先匹配语义，再写类比**：选与 Python 该点「用法/角色」最接近的一侧
- **没有靠谱对应就写没有**：用 `**无直接对应。**`（或表里写「无直接对应」），可附一句常见替代；**禁止硬凑**看似相关、实际语义不对的代码
- 同一篇笔记里，不同小节可以选不同侧（例如总览用 JS，某一节用 TS / Node）
- 文首对照表列名与所选侧一致，例如 `| Python | TypeScript 对应 |`、`| Python | JavaScript 对应 |`、`| Python | Node.js 对应 |`；若一表多行且各行所选侧不同，列名可用 `| Python | 对应（JS / TS / Node） |`，单元格写清是哪一侧

## 必须完成的改造

1. **文首对照表**  
   若该主题适合总览，在开头补对照表（或给已有总览表加对应列）。无对应时写「无直接对应」，有替代才写替代，没有就别编。

2. **类比代码块**  
   每个重要的 Python 示例代码块后，按选型跟对应侧类比，标题与围栏一致：

   ```text
   TypeScript 类比：

   ```ts
   // ...
   ```
   ```

   或 `JavaScript 类比：` + ` ```js `，或 `Node.js 类比：` + ` ```js `（Node API 示例仍可用 `js` 围栏）。

   要求：
   - 语义对齐，不是逐字翻译
   - JS/TS：优先箭头函数 / `const`；输出用 `console.log`
   - 无对应时写 `**无直接对应。**` +（可选）一句替代；不要为了凑块而写误导示例
   - 需要补充差异时用简短引用块 `> **说明：** ...`
   - 作业题保持 Python，不要为作业补类比

3. **缩进统一为 2 空格**  
   所有 `python` / `js` / `ts` 代码块内缩进改为 2 空格；删除 Tab；不要混用 4 空格。

4. **结构体例**  
   - 章节之间不要用单独的 `---` 分隔线（与已优化样本一致）
   - 保留原有章节逻辑与作业；可修正明显笔误（如「返回两个字典」实为返回函数）
   - 不删减教学内容，不借机大改大纲

5. **直接改文件**  
   原地更新目标 `.md`，不要只输出 Diff 而不写入。

## 自检

写完后快速确认：

- [ ] 无 `\t`
- [ ] 代码缩进为 2 空格
- [ ] 主要示例都有类比或已标明无直接对应（作业除外）
- [ ] 每个类比只选了 JS / TS / Node 之一，且选型合理
- [ ] 文首有对照表（或说明为何不需要）
- [ ] 体例与锚点样本一致

完成后用一两句话说明改了哪些文件、做了哪些类改造即可。
