优化当前指定的 Python 技术笔记 Markdown：补齐前端/运行时侧类比，并统一为已优化笔记的体例。

## 输入

- 用户会 `@` 一个或多个待优化的 `.md` 文件
- 若未指定文件，先问清要优化哪几个，禁止瞎猜

## 风格锚点（必须先读）

在同目录（或同级已优化笔记）中，任选 **1～2 个已优化样本** 作为体例标准，优先：

- `Python语言核心/2. 基本语法.md`
- `Python语言核心/3. 容器类型.md`
- `Python语言核心/4. 函数.md`
- `Python语言核心/5. 作用域.md`

以这些文件的实际写法为准，不要另发明体例。

## 类比选型（强制）

每个概念 / 示例只从下面三者中选 **一个最合适** 的对照侧，不要三者并列、不要拼凑：

| 候选 | 何时优先选 |
| ---- | ---------- |
| **TypeScript** | 有类型系统、装饰器、`interface`/`enum`、泛型等更贴近的对应 |
| **JavaScript** | 语言层面的通用语义（作用域、闭包、原型、普通函数/对象） |
| **Node.js** | 模块系统、文件系统、进程、包管理、运行时 API（`fs`/`path`/`Buffer` 等） |

规则：

- **先匹配语义，再写类比**：选与 Python 该点「用法/角色」最接近的一侧
- **没有靠谱对应就写没有**：只写 `**无直接对应。**` + 最多一句话说明原因或常见做法，**禁止再跟任何代码块**
- **禁止硬凑**：结构看着像、语义不一样的机制（如用类工厂假装元类、用 mixin 假装多重继承冲突）一律不写成类比代码，宁缺毋滥
- 只是「部分近似」的对应可以写代码，但必须在标题或 `> **说明：**` 里点明近似范围与关键差异
- **单一语言原则（最重要）**：一个知识点（一个小节 / 一段示例 / 一张表）只能出现**一种**语言，不得在同一处混用两种。整篇笔记可以出现多种语言，但必须按知识点分开，例如「类的创建过程」用 JavaScript、「模块加载」用 Node.js、「泛型约束」用 TypeScript
- 无对应时也要指名那一种语言，写成 `**无 JavaScript 对应。**` / `**无 TypeScript 对应。**` / `**无 Node.js 对应。**`，不要写成笼统的「无直接对应」后再牵扯别的语言
- **禁止使用简写**：正文、表格、说明中必须写全称 `JavaScript`、`TypeScript`、`Node.js`；禁止出现 `JS`、`TS`、`Node`、`JS/TS` 这类写法
- 文首对照表只能有一种语言列，列名形如 `| Python | JavaScript 对应 |` / `| Python | TypeScript 对应 |` / `| Python | Node.js 对应 |`；禁止出现 `对应（JS / TS / Node）` 这种混合列名。若该表天然跨多种语言无法收敛，就拆成多张表，每张表一种语言

## 必须完成的改造

1. **文首对照表**  
   若该主题适合总览，在开头补对照表（或给已有总览表加对应列）。无对应时写「无直接对应」，有替代才写替代，没有就别编。

2. **类比代码块**  
   每个重要的 Python 示例代码块后，按选型跟对应侧类比，标题与围栏一致：

   ```text
   TypeScript 类比：

   ```ts
   // ...
   ```
   ```

   或 `JavaScript 类比：` + ` ```js `，或 `Node.js 类比：` + ` ```js `（Node API 示例仍可用 `js` 围栏）。

   要求：
   - 语义对齐，不是逐字翻译
   - JS/TS：优先箭头函数 / `const`；输出用 `console.log`
   - 无对应时只写 `**无直接对应。**` +（可选）一句文字说明，**不补代码块**；不要为了凑块而写误导示例
   - 需要补充差异时用简短引用块 `> **说明：** ...`
   - 作业题保持 Python，不要为作业补类比

3. **缩进统一为 2 空格**  
   所有 `python` / `js` / `ts` 代码块内缩进改为 2 空格；删除 Tab；不要混用 4 空格。

4. **结构体例**  
   - 章节之间不要用单独的 `---` 分隔线（与已优化样本一致）
   - 保留原有章节逻辑与作业；可修正明显笔误（如「返回两个字典」实为返回函数）
   - 不删减教学内容，不借机大改大纲

5. **直接改文件**  
   原地更新目标 `.md`，不要只输出 Diff 而不写入。

## 自检

写完后快速确认：

- [ ] 无 `\t`
- [ ] 代码缩进为 2 空格
- [ ] 主要示例都有类比或已标明无直接对应（作业除外）
- [ ] 每个知识点只出现一种语言，同一小节 / 同一张表没有混用
- [ ] 全文没有 `JS`、`TS`、`Node` 等简写，只有 `JavaScript`、`TypeScript`、`Node.js`
- [ ] 无对应处已指名语言（如「无 JavaScript 对应」），且后面没有跟任何代码块
- [ ] 每个保留的类比都能说清它对应 Python 的哪个语义；只是部分近似的已标明差异
- [ ] 文首有对照表（或说明为何不需要）
- [ ] 体例与锚点样本一致

完成后用一两句话说明改了哪些文件、做了哪些类改造即可。
