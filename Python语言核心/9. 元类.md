元类（metaclass）是**创建类的类**。默认元类是 `type`：写 `class Dog:` 时，底层其实是在调用 `type` 去造出 `Dog` 这个类对象。

| Python | JavaScript 对应 |
| ------ | ------- |
| `type`（默认元类） | **无直接对应**（最接近 `Function`，但不可自定义） |
| `metaclass=` 指定元类 | **无直接对应** |
| 自定义元类（继承 `type`） | **无直接对应**（类工厂 / `Proxy` 近似） |
| 元类 `__new__` / `__init__` | **无直接对应**（无法干预「类被创建」这一步） |
| 元类 `__call__` | `Proxy` 的 `construct`（拦截 `new`） |
| 子类继承父类元类 | **无直接对应** |

> **说明：** JS 的类型线被 `Function` 固定住了，不能像 Python 那样写一个继承 `type` 的类去控制「类怎么被创建」。下面类比多用**类工厂**或 `Proxy` 说明意图，不是一一对应。

## 类的创建过程

使用 `class` 关键字定义类时，Python 底层会调用元类来创建类：

```python
class Dog:
  pass


# 等效于
class Dog(metaclass=type):
  pass


# 等效于
Dog = type("Dog", (), {})

# 等效于
Dog = type.__call__(type, "Dog", (), {})
```

也就是说，`class` 关键字只是语法糖，底层仍然是通过 `type()` 创建类。

**JavaScript 无直接对应。** 常见替代是**类工厂**（返回一个 `class`）：

```js
// 近似：用工厂「造出」一个类，而不是自定义元类
const createDogClass = () => {
  return class Dog {}
}

const Dog = createDogClass()
const d = new Dog()
console.log(d instanceof Dog)  // true
```

> **说明：** `type("Dog", (), {})` 在 JS 里没有等价 API。`class Dog {}` 最终仍是一个 `Function`，无法换成别的「元类」。

## 自定义元类

通过继承 `type`，可以自定义元类，控制类的创建过程。

```python
class MyMeta(type):
  def __new__(mcs, name, bases, namespace):
    print(f"正在创建类: {name}")
    print(f"父类: {bases}")
    print(f"属性: {list(namespace.keys())}")

    # 必须调用 type.__new__ 来真正创建类
    cls = super().__new__(mcs, name, bases, namespace)
    return cls


# 使用 metaclass 参数指定元类
class Dog(metaclass=MyMeta):
  species = "Canis familiaris"

  def bark(self):
    print("Woof!")


# 等效于
# def bark(self):
#   print("Woof!")


# Dog = type.__call__(MyMeta, "Dog", (), {"species": "Canis familiaris", "bark": bark})

# 输出：
# 正在创建类: Dog
# 父类: ()
# 属性: ['__module__', '__qualname__', 'species', 'bark']
```

**参数说明：**

- `mcs`：元类自身（类似类方法中的 `cls`）
- `name`：类名字符串
- `bases`：父类元组
- `namespace`：类属性的字典

**JavaScript 无直接对应。** 若只想在「定义类时」做点手脚，可用类工厂模拟部分效果：

```js
const withMeta = (name, body) => {
  console.log(`正在创建类: ${name}`)
  const cls = body()
  console.log(`属性: ${Object.getOwnPropertyNames(cls.prototype)}`)
  return cls
}

const Dog = withMeta("Dog", () => {
  return class Dog {
    static species = "Canis familiaris"
    bark() {
      console.log("Woof!")
    }
  }
})

new Dog().bark()  // Woof!
```

> **说明：** 工厂只是包装了「定义类」这件事；它**不会**成为 `Dog` 的类型，也**不会**被子类自动继承。真正的元类行为（改 `type(Dog)`、控制 `Dog()`）在 JS 里做不到。

## 深入：元类的查找顺序

子类会继承父类的元类：

```python
class MyMeta(type):
  pass

class Base(metaclass=MyMeta):
  pass

class Child(Base):  # 自动继承 MyMeta
  pass

print(type(Child))  # <class '__main__.MyMeta'>
```

**JavaScript 无直接对应。** 子类 `extends` 只继承原型链，不会多一层「元类」：

```js
class Base {}
class Child extends Base {}

console.log(Child instanceof Function)  // true（始终是 Function）
console.log(Object.getPrototypeOf(Child) === Base)  // true
```

如果父类元类不兼容，需要使用更通用的元类：

```python
class MetaA(type):
  pass

class MetaB(type):
  pass

class A(metaclass=MetaA):
  pass

class B(metaclass=MetaB):
  pass

# class C(A, B): pass  # TypeError! 元类冲突

# 解决方法：创建兼容的元类
class CommonMeta(MetaA, MetaB):
  pass

class C(A, B, metaclass=CommonMeta):  # 正常
  pass
```

**JavaScript 无直接对应。** JS 没有「多个元类冲突」问题；多重继承本身也不支持（单继承 + mixin 组合）。

```js
// 只能单继承；「冲突」一般是 mixin 方法名冲突，需人工约定优先级
const mixinA = (Base) => class extends Base { fromA() { return "A" } }
const mixinB = (Base) => class extends Base { fromB() { return "B" } }

class C extends mixinA(mixinB(Object)) {}
console.log(new C().fromA(), new C().fromB())  // A B
```

## 总结

| 概念 | 说明 |
| ---- | ---- |
| 元类 | 创建类的类，默认是 `type` |
| `__new__` | 创建类，返回类对象 |
| `__init__` | 初始化类，无返回值 |
| `__call__` | 控制类的实例化过程 |
| 应用场景 | 命名检查、自动注册、方法增强、ORM 等 |
