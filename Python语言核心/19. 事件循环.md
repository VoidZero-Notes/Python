事件循环是 asyncio 实现「单线程并发」的调度核心：在一个线程里轮询就绪回调与 I/O，避免同步阻塞白白占住 CPU。

| Python | Node.js 对应 |
| ------ | ------------ |
| `asyncio` 事件循环 | libuv 事件循环（进程内置） |
| `new_event_loop` / `set_event_loop` / `get_event_loop` | 无直接对应（循环不由用户创建） |
| `run_forever` / `stop` | 无直接对应（有活跃句柄则进程不退出） |
| `call_soon` | `setImmediate`（近似） |
| `call_later` | `setTimeout` |
| 运算密集 → 多线程；I/O 密集 → 异步 | 运算密集 → `worker_threads`；I/O 密集 → 异步 |

## 同步代码的问题

```python
import requests

def task1():
  # 任务1
  requests.post(...)  # 发送请求，阻塞线程

def task2():
  # 任务2
  pass

task1()  # task1 的阻塞导致后续任务白白等待，浪费了 CPU 资源
task2()
```

Node.js 类比：

```js
const fs = require("fs");

const task1 = () => {
  // 任务1：同步 I/O 阻塞当前线程
  fs.readFileSync("/etc/hosts");
};

const task2 = () => {
  // 任务2
};

task1(); // task1 的阻塞导致后续任务白白等待
task2();
```

> **说明：** Python 示例用网络请求阻塞；Node.js 用同步读文件表达同一问题——同步 I/O 占住单线程，后面的逻辑无法推进。

## 什么是异步

异步是一种编程模式：当有多个任务需要在**一个线程**上执行时，这种模式可以让任务不会造成线程阻塞。

![image-20260802212239981](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-02-132702.png)

Node.js 同样是「单线程 + 事件循环」模型：把 I/O 交给底层，完成后把回调放回循环调度，而不是让线程干等。

## 异步 VS 多线程

| 场景 | Python | Node.js 对应 |
| ---- | ------ | ------------ |
| 运算密集型 | 多线程 / 多进程 | `worker_threads` / 子进程 |
| I/O 密集型 | 异步（asyncio） | 异步 I/O（事件循环） |

## Python 的事件循环

事件循环是实现异步的基础手段。

### AbstractEventLoop 类

在 Python 中，一个事件循环就是一个 `AbstractEventLoop` 类的对象：

```python
import asyncio

# 创建一个新的事件循环对象
loop = asyncio.new_event_loop()

# 绑定事件循环到当前线程
asyncio.set_event_loop(loop)

# 获取当前线程的事件循环
current_loop = asyncio.get_event_loop()

print("当前事件循环:", current_loop)

# 移除事件循环绑定
asyncio.set_event_loop(None)

# 运行事件循环
# 陷入死循环，除非在循环中终止，否则后续代码永远无法得到运行
current_loop.run_forever()

# 停止事件循环
current_loop.stop()
```

**无 Node.js 对应。** Node.js 的事件循环由进程内置（libuv），启动即存在，没有对外暴露的「创建 / 绑定 / 获取 / 停止」循环对象 API。

### run_forever 方法

```python
def run_forever(self):
  """Run until stop() is called."""
  while True:
    self._run_once()
    if self._stopping:
      break
```

**无 Node.js 对应。** Node.js 没有需要手动调用的 `run_forever`；存在定时器、I/O 等活跃句柄时进程会保持运行，句柄清空后自然退出。

### \_run\_once 逻辑

`_run_once` 方法的核心，就是调度事件循环中的队列。

它要确保每次该方法运行，都能保证 ready 队列中的所有回调得到执行。

<img src="https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-02-132752.png" alt="image-20260802212752452" style="zoom:50%;" />

> 1. 检查延时队列，加入 ready
> 2. 计算等待时间 timeout
>    1. ready 有东西，timeout = 0
>    2. 延时队列还有任务，timeout = 延时队列的队首 - 当前时间
>    3. 都没有任务，timeout = None
> 3. 用 timeout 的时间阻塞线程，等待 I/O，期间有任何 I/O 任务到达，马上加入 ready
>    1. 如果 timeout 时间到达后还没有 I/O 任务，则重新处理一次延时队列
> 4. 复制 ready 队列
> 5. 执行复制的队列

**无 Node.js 对应。** Node.js 内部按 timers / poll / check 等阶段推进，与「延时队列 + ready + I/O 等待」思想相近，但不暴露与 `_run_once` 对等的公开方法。

试一试下面的代码：

```python
import asyncio

loop = asyncio.new_event_loop()

# 将函数直接放入 ready 队列
def my_ready_callback():
  print("这是一个直接进入 ready 队列的回调函数")

loop.call_soon(my_ready_callback)

# 将函数放入延迟队列，1 秒后进入 ready 队列
def my_scheduled_callback():
  print("这是一个延迟1秒后进入 ready 队列的回调函数")
  loop.stop()  # 停止事件循环

loop.call_later(1, my_scheduled_callback)

loop.run_forever()

print("事件循环已停止")
```

Node.js 类比：

```js
// call_soon ≈ setImmediate：尽快在下一轮循环执行
setImmediate(() => {
  console.log("这是一个直接进入 ready 队列的回调函数");
});

// call_later ≈ setTimeout：延迟后执行
setTimeout(() => {
  console.log("这是一个延迟1秒后进入 ready 队列的回调函数");
  // Node.js 没有 loop.stop()；无活跃句柄时进程自行退出
}, 1000);
```

> **说明：** Node.js 无需 `run_forever()`；有 `setTimeout` / `setImmediate` 等活跃句柄时进程保持运行。`setImmediate` 与 `call_soon` 都是「尽快执行」，但调度阶段不完全一致；`process.nextTick` 优先级更高，不宜简单等同。
