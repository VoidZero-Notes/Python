异常用于表示程序运行中的错误或异常情况。Python 用 `try` / `except` / `else` / `finally` 捕获与清理，用 `raise` 主动抛出。

| Python | JavaScript 对应 |
| ------ | --------------- |
| `try` / `except` | `try` / `catch` |
| `else`（无异常时执行） | 无直接对应（成功逻辑写在 `try` 末尾） |
| `finally` | `finally` |
| `raise` | `throw` |
| 裸 `raise` 重抛 | `catch` 后 `throw e` |
| `raise ... from` | `Error` 的 `cause`（ES2022） |
| 异常类层次 | `Error` 及子类（层次更浅） |
| 自定义异常 | `class X extends Error` |

## 异常的捕获

使用 `try...except` 捕获可能发生的异常。

可以捕获多个异常，并获取异常对象：

```python
try:
  number = int("abc")
except ValueError as e:
  print(f"数值错误: {e}")
except TypeError as e:
  print(f"类型错误: {e}")
else:
  print("没有异常时执行")
finally:
  print("始终会执行")
```

JavaScript 类比：

```js
try {
  const number = BigInt("abc"); // 非法字面量会抛 SyntaxError
  console.log("没有异常时执行"); // 对应 Python 的 else：写在 try 成功路径末尾
} catch (e) {
  if (e instanceof SyntaxError) {
    console.log(`数值错误: ${e.message}`);
  } else if (e instanceof TypeError) {
    console.log(`类型错误: ${e.message}`);
  } else {
    throw e; // 非预期类型继续抛出
  }
} finally {
  console.log("始终会执行");
}
```

> **说明：** JavaScript 的 `catch` 不能按类型分多个子句，需在块内用 `instanceof` 区分。`else` **无 JavaScript 对应**，无异常时的逻辑通常放在 `try` 块末尾。

```python
try:
  number = int("abc")
except ValueError as e:
  print(e.args)  # 获取异常信息
  print(e.__traceback__)  # 异常的堆栈跟踪对象
```

JavaScript 类比：

```js
try {
  BigInt("abc");
} catch (e) {
  console.log(e.message); // 错误信息（近似 e.args / str(e)）
  console.log(e.stack);   // 堆栈字符串（近似 __traceback__）
}
```

> **说明：** Python 的 `e.args` 是元组，`e.__traceback__` 是 traceback 对象；JavaScript 常见的是 `message` 字符串与 `stack` 字符串，没有同构的 args / traceback 对象 API。

## 异常类型

Python 内置异常形成层次结构，捕获父类异常可以捕获其所有子类：

```
BaseException
 ├── SystemExit          # sys.exit() 引发
 ├── KeyboardInterrupt   # Ctrl+C 引发
 └── Exception           # 常规异常的基类
      ├── ArithmeticError
      │    └── ZeroDivisionError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── TypeError
      ├── ValueError
      │    └── UnicodeError
      └── ...
```

```python
# 捕获 Exception 可以捕获几乎所有常规异常
try:
  # 可能引发各种异常的操作
  pass
except Exception as e:
  print(f"发生错误: {e}")

# 但不推荐捕获过于宽泛的异常，应尽量精确
```

JavaScript 类比：

```js
try {
  // 可能引发各种异常的操作
} catch (e) {
  // catch 会接住几乎所有 throw 出的值
  console.log(`发生错误: ${e}`);
}

// 但不推荐无差别吞掉一切；应按类型精确处理后再决定是否重抛
```

> **说明：** JavaScript 内置错误（`Error`、`TypeError`、`RangeError`、`ReferenceError` 等）层次远浅于 Python，也没有与 `Exception` / `BaseException` 对等的「常规 vs 系统退出」二分。捕获父类、覆盖子类这一用法，主要靠 `instanceof` 自己判断。

## 主动抛出异常

使用 `raise` 主动抛出异常：

```python
def withdraw(balance, amount):
  if amount > balance:
    raise ValueError("余额不足")
  if amount <= 0:
    raise ValueError("取款金额必须大于零")
  return balance - amount

try:
  withdraw(100, 200)
except ValueError as e:
  print(e)  # 余额不足
```

JavaScript 类比：

```js
const withdraw = (balance, amount) => {
  if (amount > balance) {
    throw new Error("余额不足");
  }
  if (amount <= 0) {
    throw new Error("取款金额必须大于零");
  }
  return balance - amount;
};

try {
  withdraw(100, 200);
} catch (e) {
  if (e instanceof Error) {
    console.log(e.message); // 余额不足
  } else {
    throw e;
  }
}
```

可以重新抛出当前异常：

```python
try:
  risky_operation()
except Exception:
  # 记录日志后继续抛出
  print("发生异常，准备抛出")
  raise  # 重新抛出
```

JavaScript 类比：

```js
try {
  riskyOperation();
} catch (e) {
  // 记录日志后继续抛出
  console.log("发生异常，准备抛出");
  throw e; // 重新抛出（需显式写出被捕获的对象）
}
```

> **说明：** Python 的裸 `raise` 会原样重抛当前正在处理的异常；JavaScript 必须 `throw e`（或抛出新错误），没有无操作数的 `throw`。

## 自定义异常

通过继承 `Exception` 或其子类创建自定义异常：

```python
class ValidationError(Exception):
  """参数验证失败"""
  pass

class NotFoundError(Exception):
  """资源不存在"""

  def __init__(self, resource, resource_id):
    self.resource = resource
    self.resource_id = resource_id
    super().__init__(f"{resource} (id={resource_id}) 不存在")


# 使用
def get_user(user_id):
  if user_id <= 0:
    raise ValidationError("用户ID必须大于零")
  if user_id not in user_database:
    raise NotFoundError("User", user_id)
  return user_database[user_id]
```

JavaScript 类比：

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

class NotFoundError extends Error {
  constructor(resource, resourceId) {
    super(`${resource} (id=${resourceId}) 不存在`);
    this.name = "NotFoundError";
    this.resource = resource;
    this.resourceId = resourceId;
  }
}

const getUser = (userId) => {
  if (userId <= 0) {
    throw new ValidationError("用户ID必须大于零");
  }
  if (!(userId in userDatabase)) {
    throw new NotFoundError("User", userId);
  }
  return userDatabase[userId];
};
```

## 异常链

```python
def exception_chains1():
  # 方式1：直接抛出（无关联）
  try:
    raise ValueError("错误A")
  except ValueError:
    raise RuntimeError("错误B")  # 隐式关联，__context__ 有值


def exception_chains2():
  # 方式2：from 显式关联
  try:
    raise ValueError("错误A")
  except ValueError as e:
    raise RuntimeError("错误B") from e  # 显式关联，__cause__ 有值


# 查看区别
try:
  exception_chains1()
except RuntimeError as e:
  print("隐式关联:", e)
  print(f"  __cause__: {e.__cause__}")  # None
  print(f"  __context__: {e.__context__}")  # ValueError

try:
  exception_chains2()
except RuntimeError as e:
  print("\n显式关联:", e)
  print(f"  __cause__: {e.__cause__}")  # ValueError
  print(f"  __context__: {e.__context__}")  # None
```

`raise ... from`（显式关联）的 JavaScript 类比：

```js
const exceptionChains2 = () => {
  try {
    throw new Error("错误A");
  } catch (e) {
    throw new Error("错误B", { cause: e }); // 显式关联，对应 __cause__
  }
};

try {
  exceptionChains2();
} catch (e) {
  console.log("显式关联:", e.message);
  console.log("  cause:", e.cause); // Error: 错误A
}
```

> **说明：** ES2022 的 `Error` `cause` 对应 Python 的 `__cause__` / `raise ... from`。在 `except` 里直接再 `raise` 另一种异常时自动写入的 `__context__`（隐式关联）**无 JavaScript 对应**。
