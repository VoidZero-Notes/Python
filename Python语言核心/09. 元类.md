元类（metaclass）是**创建类的类**。默认元类是 `type`：写 `class Dog:` 时，底层其实是在调用 `type` 去造出 `Dog` 这个类对象。

| Python | TypeScript 对应 |
| ------ | ------- |
| `type`（默认元类） | 无直接对应 |
| `metaclass=` 指定元类 | 无直接对应 |
| 自定义元类（继承 `type`） | 无直接对应 |
| 元类 `__new__` / `__init__` | 类装饰器（介入类的定义，可返回替换后的类） |
| 元类 `__call__` | 无直接对应（`Proxy` 的 `construct` 可拦截 `new`，但要用代理替换类本身） |
| 子类继承父类元类 | 无直接对应 |
| 元类冲突 | 无直接对应 |

> **说明：** TypeScript 中类始终是一个 `Function`，语言不暴露「类由谁创建」这一层，所以元类**整体没有对应物**。唯一语义接近的只有类装饰器：它同样在类定义时介入、同样可以返回替换后的类。

## 类的创建过程

使用 `class` 关键字定义类时，Python 底层会调用元类来创建类：

```python
class Dog:
  pass

# 等效于
class Dog(metaclass=type):
  pass

# 等效于
Dog = type("Dog", (), {})

# 等效于
Dog = type.__call__(type, "Dog", (), {})
```

也就是说，`class` 关键字只是语法糖，底层仍然是通过 `type()` 创建类。

**无 JavaScript 对应。** JavaScript 没有 `type("Dog", (), {})` 这种「用类名 + 父类 + 属性字典造出一个类」的 API；`class Dog {}` 产出的对象恒为 `Function`，也无法替换成别的「元类」。

## 自定义元类

通过继承 `type`，可以自定义元类，控制类的创建过程。

```python
class MyMeta(type):
  def __new__(mcs, name, bases, namespace):
    print(f"正在创建类: {name}")
    print(f"父类: {bases}")
    print(f"属性: {list(namespace.keys())}")

    # 必须调用 type.__new__ 来真正创建类
    cls = super().__new__(mcs, name, bases, namespace)
    return cls


# 使用 metaclass 参数指定元类
class Dog(metaclass=MyMeta):
  species = "Canis familiaris"

  def bark(self):
    print("Woof!")


# 等效于
# def bark(self):
#   print("Woof!")
#
# Dog = type.__call__(MyMeta, "Dog", (), {"species": "Canis familiaris", "bark": bark})

# 输出：
# 正在创建类: Dog
# 父类: ()
# 属性: ['__module__', '__qualname__', 'species', 'bark']
```

**参数说明：**

- `mcs`：元类自身（类似类方法中的 `cls`）
- `name`：类名字符串
- `bases`：父类元组
- `namespace`：类属性的字典

TypeScript 类比（只对应「在类定义时介入、并可返回替换后的类」这一点）：

```ts
const logClass = <T extends new (...args: any[]) => any>(cls: T): T => {
  console.log(`正在创建类: ${cls.name}`)
  console.log(`属性: ${Object.getOwnPropertyNames(cls.prototype)}`)
  return cls
}

@logClass
class Dog {
  static species = "Canis familiaris"

  bark() {
    console.log("Woof!")
  }
}

new Dog().bark()  // Woof!
```

> **说明：** 类装饰器是在类**已经被创建之后**才拿到它，能读、能改、能返回替换类，但改不了 `Dog` 的类型（永远是 `Function`），也**不会被子类自动继承**。因此 TypeScript 类装饰器在 Python 里真正对等的是**类装饰器**（`@decorator` 修饰 class），元类比它更底层：元类介入的是「类如何被造出来」。

## 深入：元类的查找顺序

子类会继承父类的元类：

```python
class MyMeta(type):
  pass

class Base(metaclass=MyMeta):
  pass

class Child(Base):  # 自动继承 MyMeta
  pass

print(type(Child))  # <class '__main__.MyMeta'>
```

**无 JavaScript 对应。** JavaScript 的 `extends` 只延长原型链，类的类型恒为 `Function`，不存在「元类随继承传递」这一层机制。

如果父类元类不兼容，需要使用更通用的元类：

```python
class MetaA(type):
  pass

class MetaB(type):
  pass

class A(metaclass=MetaA):
  pass

class B(metaclass=MetaB):
  pass

# class C(A, B): pass  # TypeError! 元类冲突

# 解决方法：创建兼容的元类
class CommonMeta(MetaA, MetaB):
  pass

class C(A, B, metaclass=CommonMeta):  # 正常
  pass
```

**无 JavaScript 对应。** JavaScript 只有单继承（多重继承靠 mixin 组合），也没有元类，因此不存在「多个元类需要合并」的问题。

## 总结

| 概念 | 说明 |
| ---- | ---- |
| 元类 | 创建类的类，默认是 `type` |
| `__new__` | 创建类，返回类对象 |
| `__init__` | 初始化类，无返回值 |
| `__call__` | 控制类的实例化过程 |
| 应用场景 | 命名检查、自动注册、方法增强、ORM 等 |

## 实践：实现一个单例元类

```python
class SingletonMeta(type):
  _instance = {}

  def __call__(self, *args, **kwds):
    if self not in self._instance:
      ins = super().__call__(*args, **kwds)
      self._instance[self] = ins

    return self._instance[self]

class Database(metaclass=SingletonMeta):
  def __init__(self, host):
    self.host = host

db1 = Database('localhost')
db2 = Database('remote')

print(db1 is db2) # True
print(db1.host) # localhost
```

## 实践：自动注册子类

```python
class PluginMeta(type):
  registry = {}

  def __new__(mcs, name, bases, namespace):
    cls = super().__new__(mcs, name, bases, namespace)
    if name != 'Plugin':
      mcs.registry[name] = cls
    return cls

class Plugin(metaclass=PluginMeta):
  pass

class ImagePlugin(Plugin):
  pass

class TextPLugin(Plugin):
  pass

print(PluginMeta.registry) # {'ImagePlugin': <class '__main__.ImagePlugin'>, 'TextPLugin': <class '__main__.TextPLugin'>}
```

## 实践：为所有方法添加日志

```python
class LogMeta(type):
  def __new__(mcs, name, bases, namespace):
    for key, value in namespace.items():
      if not key.startswith('_') and callable(value):
        namespace[key] = mcs.log_wrapper(value)
    return super().__new__(mcs, name, bases, namespace)

  @staticmethod
  def log_wrapper(func):
    def wrapper(*args, **kwargs):
      print(f"[LOG] call {func.__name__}")
      return func(*args, **kwargs)
    return wrapper

class Calculator(metaclass=LogMeta):
  def add(self, a, b):
    return a + b

  def sub(self, a, b):
    return a - b

calc = Calculator()

print(calc.add(3, 5))
print(calc.sub(10, 4))

"""
[LOG] call add
8
[LOG] call sub
6
"""
```
