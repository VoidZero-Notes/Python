装饰器（decorator）是一种**语法糖**：用 `@` 把一个可调用对象包在另一个外面，常用来在不改原函数定义的前提下增强行为（日志、计时、鉴权等）。

| Python              | TypeScript 对应                                                 |
| ------------------- | --------------------------------------------------------------- |
| `@decorator` 语法糖 | `@decorator`（需开启装饰器相关编译选项）                        |
| 装饰器（高阶函数）  | 装饰器工厂 / 返回新函数的包装器                                 |
| 装饰自由函数        | **无直接对应**（TypeScript 装饰器主要挂在 class / method 等上） |
| 类装饰器            | 类装饰器（改 `prototype` / 返回原类或新类）                     |
| `@a` `@b` 叠加      | 多个 `@` 叠加（靠近声明的先包）                                 |
| `functools.wraps`   | **无直接对应**（需手动保留 `name` 等）                          |

## 装饰器的本质

装饰器本质上是一个接受函数作为参数并返回新函数的高阶函数：

```python
def my_decorator(func):
  def wrapper():
    print("函数执行前")
    func()
    print("函数执行后")
  return wrapper

# 下面的代码
def say_hello():
  print("Hello!")
say_hello = my_decorator(say_hello)

# 等效于
@my_decorator
def say_hello():
  print("Hello!")

say_hello()
# 输出：
# 函数执行前
# Hello!
# 函数执行后
```

TypeScript 类比（`@` 用在类方法上；语义仍是「包装后再替换」）：

```ts
function myDecorator(
  _target: object,
  _key: string | symbol,
  descriptor: PropertyDescriptor,
) {
  const original = descriptor.value as () => void;
  descriptor.value = function wrapper(this: unknown) {
    console.log("函数执行前");
    original.call(this);
    console.log("函数执行后");
  };
  return descriptor;
}

class Greeter {
  @myDecorator
  sayHello() {
    console.log("Hello!");
  }
}

new Greeter().sayHello();
// 输出：
// 函数执行前
// Hello!
// 函数执行后
```

> **说明：** Python 的 `@` 可装饰自由函数；TypeScript 装饰器主要作用在 **类及相关成员** 上。若只谈「高阶函数包装」本身，两边写法相同：`fn = decorator(fn)`，不必依赖 `@`。

**装饰器是一个可调用对象，接收一个可调用对象，返回任意对象。但为了保证程序能正常运行，通常返回另一个可调用对象来替代原对象。**

## 多个装饰器叠加

可以同时使用多个装饰器，执行顺序为从下到上：

```python
@decorator_a
@decorator_b
def func():
  pass

# 等效于：
# func = decorator_a(decorator_b(func))
```

TypeScript 类比：

```ts
function decoratorA(
  _t: object,
  _k: string | symbol,
  descriptor: PropertyDescriptor,
) {
  console.log("A 包装");
  return descriptor;
}

function decoratorB(
  _t: object,
  _k: string | symbol,
  descriptor: PropertyDescriptor,
) {
  console.log("B 包装");
  return descriptor;
}

class Demo {
  @decoratorA
  @decoratorB
  method() {}
}

// 靠近声明的先应用：先 B 后 A
// 约等于 method = decoratorA(decoratorB(method))
```

## 实践：timer 装饰器

计时是装饰器的常见用途。实现一个 `timer`，打印被装饰函数的执行耗时：

```python
import time

def timer(func):
  def wrapper(*args, **kwargs):
    start = time.time()
    result = func(*args, **kwargs)
    elapsed = time.time() - start
    print(f"{func.__name__} 执行时间: {elapsed:.4f} 秒")
    return result
  return wrapper

@timer
def slow_function():
  time.sleep(1)
  return "Done"

slow_function()
# 输出：slow_function 执行时间: 1.0012 秒
```

要点：

- `wrapper(*args, **kwargs)`：兼容有参函数
- `return result`：保留原函数返回值
- `{elapsed:.4f}`：固定 4 位小数（写成 `.4` 格式不对）

## 实践：wraps 装饰器

装饰后函数的 `__name__`、`__doc__` 会变成 `wrapper` 的。手写一个简化版 `wraps`，把原函数的名称和文档注释拷回去：

```python
def wraps(func):
  def decorator(wrapper):
    wrapper.__name__ = func.__name__
    wrapper.__doc__ = func.__doc__
    return wrapper
  return decorator

def my_decorator(func):
  @wraps(func)
  def wrapper():
    print("函数执行前")
    func()
    print("函数执行后")
  return wrapper

@my_decorator
def say_hello():
  """打招呼"""
  print("Hello!")

say_hello()
# 函数执行前
# Hello!
# 函数执行后
print("name", say_hello.__name__)  # name say_hello
print("doc", say_hello.__doc__)    # doc 打招呼
```

要点：

- `@wraps(func)` 发生在**定义 `wrapper` 时**，不是调用时。等价于 `wrapper = wraps(func)(wrapper)`：先拿到内层 `decorator`，再立刻改掉 `wrapper` 的 `__name__` / `__doc__`，然后 `return wrapper`。外面拿到时元信息已经对了
- 时间线：进入 `my_decorator` → 定义出 `wrapper` → `@wraps(func)` 马上改元信息 → `return wrapper` → 之后才轮到调用 `say_hello()`。不是 `@` 有魔法，而是装饰器工厂在定义阶段就跑完了
- 若把 `wrapper.__name__ = ...` 写进 `wrapper` 函数体里，要等**调用**时才赋值。先调用再打印，看起来和 `@wraps` 一样；但调用前打印仍是 `"wrapper"` / `None`。`help()`、`inspect`、调试栈往往不会先调用函数，所以必须在装饰阶段改
- 实际项目用标准库 `functools.wraps`（还会处理 `__module__`、`__qualname__`、`__annotations__` 等）；上面是只保留 `__name__` / `__doc__` 的简化版

## 实践：cache 装饰器

缓存函数的计算结果。相同参数再次调用时，直接返回缓存值（递归斐波那契若不缓存会极慢）：

```python
def cache(func):
  _cache = {}

  def wrapper(*args, **kwargs):
    key = (args, tuple(kwargs.items()))
    if key not in _cache:
      _cache[key] = func(*args, **kwargs)
    return _cache[key]

  return wrapper

@cache
def fibonacci(n):
  if n < 2:
    return n
  return fibonacci(n - 1) + fibonacci(n - 2)

print(fibonacci(35)) # 9227465
```

JavaScript 类比（高阶函数包装，语义同「记忆化」）：

```js
const cache = (fn) => {
  const memo = new Map();

  const wrapper = (...args) => {
    const key = JSON.stringify(args);
    if (memo.has(key)) {
      return memo.get(key);
    }
    const result = fn(...args);
    memo.set(key, result);
    return result;
  };

  return wrapper;
};

const fibonacci = cache((n) => {
  if (n < 2) {
    return n;
  }
  return fibonacci(n - 1) + fibonacci(n - 2);
});

console.log(fibonacci(35)); // 9227465
```

要点：

- `_cache` / `memo` 放在外层闭包里，多次调用共享同一份缓存
- 用参数做成 key；命中则跳过计算。JavaScript 侧用 `memo.has(key)`，避免结果为 `0` 等假值时误判未缓存
- `@cache` 后递归调用的是包装后的函数，中间结果也会进缓存，所以 `fibonacci(35)` 才能快
- 实际项目可用 `functools.lru_cache`；上面是手写简化版

## 实践：to_dict 类装饰器

类装饰器接收的是**类本身**（不是函数）。给类挂上 `to_dict`，把实例转成字典：

```python
def to_dict(cls):
  def to_dict_method(self):
    return self.__dict__

  cls.to_dict = to_dict_method
  return cls

@to_dict
class Point:
  def __init__(self, x, y):
    self.x = x
    self.y = y

p = Point(3, 4)
print(p.to_dict())  # {'x': 3, 'y': 4}
```

TypeScript 类比（类装饰器改 `prototype`；语义同「给类挂方法」）：

```ts
type Constructor = new (...args: any[]) => object;

const to_dict = <T extends Constructor>(cls: T) => {
  cls.prototype.to_dict = function (this: InstanceType<T>) {
    return { ...this };
  };
  return cls;
};

@to_dict
class Point {
  x: number;
  y: number;

  constructor(x: number, y: number) {
    this.x = x;
    this.y = y;
  }
}

interface Point {
  to_dict(): { x: number; y: number };
}

const p = new Point(3, 4);
console.log(p.to_dict()); // { x: 3, y: 4 }
```

要点：

- `@to_dict` 等价于 `Point = to_dict(Point)`：入参是类，改完再返回类
- Python 用 `self.__dict__` 拿实例属性；TypeScript 侧挂到 `prototype`，用 `{ ...this }` 浅拷贝可枚举自有属性
- TypeScript 运行时挂上的方法不会自动进类型，所以用 `interface Point` 合并声明补上 `to_dict` 的类型
- 需开启 TypeScript 装饰器相关编译选项（如 `experimentalDecorators`）
