Python 里**一切皆对象**——数字、函数、类本身都是对象。这一篇把三个问题串起来讲清楚：对象的**类型**是什么、对象是**怎么被创建**的、成员是**怎么被找到**的。

这三件事其实是一条链：

> 类也是对象 → 类是**可调用对象** → 调用类（`A()`）就触发了**创建流程**（`__new__` + `__init__`）→ 创建好的对象按**查找顺序**访问成员

| Python | JavaScript 对应 |
| ------ | ------- |
| `type(obj)` | `obj.constructor` / `Object.getPrototypeOf` |
| `type`（创建类的类，元类） | **无直接对应**（最接近 `Function`，但不可自定义） |
| `object`（所有类的根父类） | `Object.prototype` |
| `function`（函数的类型） | `Function` |
| `isinstance(x, type)` 判断是不是类 | **无直接对应**（类和函数都是 `typeof === "function"`） |
| `callable(x)` | `typeof x === "function"` |
| `__call__` 让实例可调用 | **无直接对应**（用闭包或 `Proxy` 的 `apply`） |
| `__new__` 分配实例 | `new` 的内部步骤（不可单独干预） |
| `__init__` 初始化实例 | `constructor` |
| `__new__` 返回别的对象 | `constructor` 里 `return 某个对象`（覆盖 `this`） |
| 实例成员查找 | 实例 → `prototype` 原型链 |
| 类成员查找（`__mro__` → 元类 `__mro__`） | 类 → 父类（静态继承链）→ `Function.prototype` |

## 对象的类型

所有的对象都是通过类创建的，创建对象的类，称之为该对象的类型（也有所属类的说法）

可以使用`type(对象)`得到某个对象的类型

![image-20260726225840849](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-07-26-145840.png)

- 所有函数的类型是`function`
- 所有类的类型是`type`
- **创建类的类，称之为元类（metaclass）**

### 验证代码

`function` 类没有对外暴露名字，需要通过 `type(lambda: None)` 拿到：

```python
function = type(lambda: None)

# type
print(type(type))                    # <class 'type'>
print(isinstance(type, type))        # True
print(isinstance(type, function))    # False
print(isinstance(type, object))      # True

# object
print(type(object))                  # <class 'type'>
print(isinstance(object, type))      # True
print(isinstance(object, function))  # False

# function
print(type(function))                # <class 'type'>
print(isinstance(function, object))  # True
print(isinstance(function, type))    # True
print(isinstance(function, function))  # False


# 普通对象和类
class A:
  pass

a = A()
print(type(a))                       # <class '__main__.A'>
print(type(A))                       # <class 'type'>
print(isinstance(A, A))              # False
print(isinstance(A, object))         # True
print(isinstance(A, type))           # True
print(isinstance(A, function))       # False
print(isinstance(a, A))              # True
print(isinstance(a, object))         # True
print(isinstance(a, type))           # False
print(isinstance(a, function))       # False


# 普通函数
def func():
  pass

print(type(func))                    # <class 'function'>
print(isinstance(func, object))      # True
print(isinstance(func, type))        # False
print(isinstance(func, function))    # True
```

### 从结果中得到的结论

| 结论 | 依据 |
| ---- | ---- |
| `type` 的类型是它自己，**类型链的终点** | `type(type)` 是 `type` |
| `object` 也是一个类，它的类型是 `type` | `type(object)` 是 `type` |
| `function` 也是一个类（不是函数），它的类型是 `type` | `type(function)` 是 `type`、`isinstance(function, type)` 为 `True` |
| 一切皆对象，所以一切都是 `object` 的实例 | `isinstance(type, object)`、`isinstance(function, object)` 都为 `True` |
| **判断“某个东西是不是类”，用 `isinstance(x, type)`** | 类 `A` 为 `True`，实例 `a`、函数 `func` 为 `False` |
| 类是元类的实例，不是自己的实例 | `isinstance(A, A)` 为 `False`，`isinstance(A, type)` 为 `True` |
| 函数是 `function` 的实例，不是类 | `isinstance(func, function)` 为 `True`、`isinstance(func, type)` 为 `False` |

这里最容易绕晕的是 `type` 和 `object` 的关系，两者是**两条不同的线**：

- **继承线（`__mro__`）**：谁是谁的父类，终点是 `object`
- **类型线（`type()`）**：谁创建了谁，终点是 `type`

```python
print(type.__mro__)   # (type, object)      →  type 继承自 object
print(type(object))   # <class 'type'>      →  object 由 type 创建
```

也就是说 `type` 继承 `object`，同时 `object` 又由 `type` 创建，两者互相依赖，这是解释器在底层写死的，不需要用 Python 层面的逻辑去解释。

JavaScript 类比（同样有两条线，只是名字不同）：

```js
class Base {}
class A extends Base {}
const a = new A()

// 类型线：谁创建了我
console.log(a.constructor === A)               // true   ↔ type(a) is A
console.log(typeof A)                          // function
console.log(A instanceof Function)             // true   ↔ isinstance(A, type)

// 继承线：谁是我的父类
console.log(Object.getPrototypeOf(A) === Base) // true   ↔ A.__mro__ 里有 Base
console.log(a instanceof Base)                 // true
```

> **说明：** JS 里类和普通函数的 `typeof` 都是 `"function"`，没法像 Python 用 `isinstance(x, type)` 精确区分“是不是类”（只能靠 `Function.prototype.toString()` 是否以 `class` 开头这种 hack）。Python 的类型线是显式的一层对象（元类），JS 的类型线被 `Function` 固定住了，不能自定义。

## 可调用对象

**可调用对象（Callable）**指可以像函数一样加括号 `()` 调用的对象。

上一节得出「类是元类 `type` 的实例」，而 `type` 上定义了 `__call__`，所以**类天生就是可调用对象**——这正是 `A()` 能创建实例的原因。

### 判断是否可调用

使用内置函数 `callable()`：

```python
print(callable(len))        # True，内置函数
print(callable(int))        # True，类
print(callable([1, 2]))     # False，列表不可调用
print(callable(lambda: 1))  # True，lambda 表达式
```

JavaScript 类比：

```js
console.log(typeof (() => 1) === "function")   // true
console.log(typeof Array === "function")       // true，类/构造函数
console.log(typeof [1, 2] === "function")      // false
```

函数是最常见的可调用对象：

```python
def greet(name):
  return f"Hello, {name}!"

print(callable(greet))  # True
print(greet("Alice"))   # Hello, Alice!
```

类也是可调用对象，**调用类就是创建实例**：

```python
class Dog:
  def __init__(self, name):
    self.name = name

print(callable(Dog))    # True
my_dog = Dog("Buddy")   # 调用类，创建实例
print(my_dog.name)      # Buddy
print(callable(my_dog))  # False，实例默认不可调用
```

JavaScript 类比：

```js
class Dog {
  constructor(name) {
    this.name = name
  }
}

console.log(typeof Dog === "function")   // true
const myDog = new Dog("Buddy")           // 必须写 new
console.log(myDog.name)                  // Buddy
console.log(typeof myDog === "function") // false
```

> **说明：** Python 调用类不写 `new`，`Dog("Buddy")` 就是创建实例；JS 的 `class` 反过来**必须**写 `new`，直接 `Dog("Buddy")` 会抛 `TypeError`。

### 让实例变成可调用对象

在类中定义 `__call__` 方法，**实例**就可以像函数一样调用：

```python
class Adder:
  def __init__(self, n):
    self.n = n

  def __call__(self, x):
    return self.n + x

add_5 = Adder(5)
print(callable(add_5))          # True
print(add_5(10))                # 15，像函数一样调用
print(Adder.__call__(add_5, 10))  # 15，add_5(10) 的等价写法
```

没有定义 `__call__` 的实例调用会直接报错：

```python
class NoCall:
  pass

NoCall()()  # TypeError: 'NoCall' object is not callable
```

**关键理解：**

- `__call__` 定义在**类**上，生效对象是**实例**
- 想让「类本身」可调用时做手脚，就得把 `__call__` 定义在**元类**上（见下一节）
- 调用实例时传的参数，全部转交给 `__call__`

**JavaScript 无直接对应。** 对象不能加括号调用，只有函数可以。最常见的替代是**闭包**——用函数捕获状态，再往函数上挂属性：

```js
const createAdder = (n) => {
  const add = (x) => n + x
  add.n = n  // 函数也是对象，可以挂“实例属性”
  return add
}

const add5 = createAdder(5)
console.log(typeof add5 === "function")  // true
console.log(add5(10))                    // 15
console.log(add5.n)                      // 5
```

如果一定要“一个对象既能调用又能当对象用”，可以用 `Proxy` 代理一个空函数：

```js
class Adder {
  constructor(n) {
    this.n = n
  }
  call(x) {
    return this.n + x
  }
}

const asCallable = (obj) =>
  new Proxy(function () {}, {
    apply: (_target, _thisArg, args) => obj.call(...args),
    get: (_target, key) => obj[key],
  })

const add5 = asCallable(new Adder(5))
console.log(add5(10))  // 15
console.log(add5.n)    // 5
```

### 应用场景

#### 1. 可配置的函数对象

同一份逻辑，用不同配置生成多个“函数”：

```python
class Multiplier:
  def __init__(self, factor):
    self.factor = factor

  def __call__(self, value):
    return self.factor * value

double = Multiplier(2)
triple = Multiplier(3)

print(double(5))   # 10
print(triple(5))   # 15
```

JavaScript 类比（这就是 JS 里最日常的高阶函数写法）：

```js
const multiplier = (factor) => (value) => factor * value

const double = multiplier(2)
const triple = multiplier(3)

console.log(double(5))  // 10
console.log(triple(5))  // 15
```

#### 2. 状态保持的回调函数

调用之间需要记住状态时，`__call__` 比闭包更直观（状态是显式的实例属性）：

```python
class Logger:
  def __init__(self, prefix):
    self.prefix = prefix
    self.log_count = 0

  def __call__(self, message):
    self.log_count += 1
    print(f"[{self.prefix}] #{self.log_count}: {message}")

error_log = Logger("ERROR")
error_log("文件未找到")      # [ERROR] #1: 文件未找到
error_log("网络连接失败")    # [ERROR] #2: 网络连接失败
print(error_log.log_count)  # 2，状态可以从外部读取
```

JavaScript 类比：

```js
const createLogger = (prefix) => {
  let logCount = 0
  const log = (message) => {
    logCount += 1
    console.log(`[${prefix}] #${logCount}: ${message}`)
  }
  log.getCount = () => logCount  // 想从外部读状态，得手动暴露
  return log
}

const errorLog = createLogger("ERROR")
errorLog("文件未找到")        // [ERROR] #1: 文件未找到
errorLog("网络连接失败")      // [ERROR] #2: 网络连接失败
console.log(errorLog.getCount())  // 2
```

> **说明：** 两者能力等价，差别在状态的可见性。Python 的状态是实例属性，天然可读可改；JS 闭包变量默认外部读不到，要额外暴露方法。

## 对象的创建过程

有了前两节的铺垫，`Person("shae", 5)` 到底发生了什么就能说清楚了：

**`Person` 是元类 `type` 的实例 → 调用 `Person()` 实际是执行 `type.__call__(Person, "shae", 5)` → 这个 `__call__` 内部依次调用 `__new__` 和 `__init__`。**

```python
class Meta(type):
  def __call__(cls, *args, **kwargs):
    print("Meta.__call__ 被触发")   # 调用类时，走的是元类的 __call__
    return super().__call__(*args, **kwargs)

class P(metaclass=Meta):
  def __new__(cls, *args, **kwargs):
    print("P.__new__")
    return super().__new__(cls)

  def __init__(self, name):
    print("P.__init__")
    self.name = name

p = P("shae")
# Meta.__call__ 被触发
# P.__new__
# P.__init__
```

### 创建流程的伪代码

`type.__call__` 内部做的事，用 Python 写出来大致是：

```python
def create_object(cls, *args, **kwargs):
  # 1. 调用 __new__ 创建实例
  obj = cls.__new__(cls, *args, **kwargs)

  # 2. 类型检查：只有 obj 是 cls 的实例（或其子类的实例）时才调用 __init__
  if isinstance(obj, cls):
    obj.__init__(*args, **kwargs)

  # 3. 返回对象
  return obj


# 测试
class Person:
  def __init__(self, name, age):
    self.name = name
    self.age = age

  def sayHi(self):
    print(f"my name is {self.name}, I'm {self.age} years old")

p = create_object(Person, "shae", 5)
p.sayHi()   # my name is shae, I'm 5 years old
```

三个要点：

| 要点 | 说明 |
| ---- | ---- |
| `__new__` | **创建**并返回实例，第一个参数是 `cls`（类），本质是静态方法 |
| `__init__` | **初始化**已有实例，第一个参数是 `self`（实例），不能返回值（只能返回 `None`） |
| 类型检查 | `__new__` 返回的东西不是 `cls` 的实例时，**`__init__` 直接被跳过** |

绝大多数类只写 `__init__`，此时 `__new__` 用的是继承来的 `object.__new__`：

```python
print(Person.__new__ is object.__new__)  # True，没重写就是用父类的
```

JavaScript 类比：`new Person(...)` 的内部步骤（创建对象、绑定原型、执行 `constructor`）是引擎固定的，`constructor` 只对应 `__init__`：

```js
class Person {
  constructor(name, age) {
    this.name = name
    this.age = age
  }

  sayHi() {
    console.log(`my name is ${this.name}, I'm ${this.age} years old`)
  }
}

const p = new Person("shae", 5)
p.sayHi()  // my name is shae, I'm 5 years old
```

> **说明：** JS 没有独立的 `__new__` 钩子，但 `constructor` 里 `return 一个对象` 会**覆盖默认的 `this`**，效果接近 `__new__` 的“决定返回谁”。下面的单例、对象池就是靠这个特性实现的。

### 应用场景

理解创建过程后，就能通过重写 `__new__` 控制“到底返回哪个对象”，实现多种设计模式。

#### 1. 单例模式

确保一个类只有一个实例：

```python
class Database:
  _instance = None

  def __new__(cls):
    if cls._instance is None:
      cls._instance = super().__new__(cls)
    return cls._instance

conn1 = Database()
conn2 = Database()
print(conn1 is conn2)  # True，说明是同一个实例
```

JavaScript 类比（利用 `constructor` 返回对象覆盖 `this`）：

```js
class Database {
  static #instance

  constructor() {
    if (Database.#instance) return Database.#instance  // 返回对象会覆盖 this
    Database.#instance = this
  }
}

const conn1 = new Database()
const conn2 = new Database()
console.log(conn1 === conn2)  // true
```

#### 2. 对象池 / 缓存

复用已有对象，避免重复创建：

```python
class ConnectionPool:
  _pool = {}

  def __new__(cls, conn_id):
    if conn_id not in cls._pool:
      cls._pool[conn_id] = super().__new__(cls)
    return cls._pool[conn_id]

pool1 = ConnectionPool("conn_1")
pool2 = ConnectionPool("conn_1")
pool3 = ConnectionPool("conn_2")
print(pool1 is pool2)  # True，相同 conn_id 返回同一个对象
print(pool1 is pool3)  # False，不同 conn_id 返回不同对象
```

JavaScript 类比：

```js
class ConnectionPool {
  static #pool = new Map()

  constructor(connId) {
    const cached = ConnectionPool.#pool.get(connId)
    if (cached) return cached
    this.connId = connId
    ConnectionPool.#pool.set(connId, this)
  }
}

const pool1 = new ConnectionPool("conn_1")
const pool2 = new ConnectionPool("conn_1")
const pool3 = new ConnectionPool("conn_2")
console.log(pool1 === pool2)  // true
console.log(pool1 === pool3)  // false
```

#### 3. 返回其他类型（带默认值回退）

`__new__` 可以返回**任意**对象。当返回的对象不是当前类的实例时，按前面的伪代码，`__init__` 不会被执行：

```python
class PositiveInt:
  def __new__(cls, value):
    if value < 0:
      return 0  # 返回 int 类型的 0，不是 PositiveInt 的实例
    return super().__new__(cls)

  def __init__(self, value):
    print("PositiveInt.__init__ 被调用")
    self.value = value

p = PositiveInt(5)
print(type(p))    # <class '__main__.PositiveInt'>
print(p.value)    # 5

n = PositiveInt(-3)   # 注意：这里没有打印 "__init__ 被调用"
print(type(n))    # <class 'int'>
print(n)          # 0
```

**JavaScript 无直接对应。** `constructor` 只有返回**对象**才会覆盖 `this`，返回原始值会被静默忽略：

```js
class PositiveInt {
  constructor(value) {
    if (value < 0) return 0  // 原始值，被忽略！
    this.value = value
  }
}

const n = new PositiveInt(-3)
console.log(n instanceof PositiveInt)  // true，并没有变成 0
console.log(n.value)                   // undefined
```

想实现同样的效果，只能放弃 `new`，改用工厂函数：

```js
const positiveInt = (value) => (value < 0 ? 0 : { value })

console.log(positiveInt(5))   // { value: 5 }
console.log(positiveInt(-3))  // 0
```

## 成员的查找顺序

### 只有一条规则

访问 `x.name` 时，Python 永远是这两步：

1. 先找 **x 自身**
2. 再找 **x 的类型**（只往上走一层类型，不会再上一层）

之所以看起来有两套规则，是因为**“自身”对类和对实例的含义不一样**：

| 访问对象 | 第 1 步：自身 | 第 2 步：它的类型 |
| -------- | ------------- | ----------------- |
| 普通实例 `a.name` | `a.__dict__`（实例只有自己，没有继承链） | `type(a).__mro__`，即 `A → 父类 → object` |
| 类 `A.name` | `A.__mro__`，即 `A → 父类 → object`（类之间有继承，所以“自身”是一整条链） | `type(A).__mro__`，即 `元类 → type → object` |

**继承只发生在类与类之间**，实例不参与继承。所以实例的“自身”只是一个属性字典，而类的“自身”会顺着 MRO 一路找下去。

### 代码验证

```python
class Meta(type):
  who = "Meta"
  meta_only = "只有元类有"

class Base:
  who = "Base"
  base_only = "只有Base有"

class A(Base, metaclass=Meta):
  who = "A"
  a_only = "只有A有"

a = A()

print(A.__mro__)        # (A, Base, object)        ← A 自身的链条
print(type(A).__mro__)  # (Meta, type, object)     ← 元类的链条
```

**类的查找**：先走自身 MRO，走完才去元类 MRO

```python
print(A.who)        # A          ← A 自己有，直接命中
print(A.base_only)  # 只有Base有  ← A 没有，沿 MRO 在父类找到
print(A.meta_only)  # 只有元类有  ← 自身 MRO 全找不到，才去元类链条找
```

注意 `who` 在 `A`、`Base`、`Meta` 里都定义了，结果是 `A`：**自身 MRO 的优先级高于元类 MRO**。

**实例的查找**：先找自身字典，再走类的 MRO，**到此结束**

```python
print(a.who)        # A          ← 自身没有，去 type(a).__mro__ 找到
print(a.base_only)  # 只有Base有  ← 同上，沿 MRO 找到父类
print(a.meta_only)  # AttributeError: 'A' object has no attribute 'meta_only'
```

`a.meta_only` 报错是这一节的关键：**实例只往上走一层类型（`A` 的 MRO），不会继续走到 `A` 的类型（元类）**。元类上的成员，只有类能访问，实例访问不到。

反过来也一样，实例属性挂在实例自己的字典里，类不可能找到：

```python
class E:
  def __init__(self):
    self.only_inst = 1

e = E()
print(e.only_inst)  # 1
print(E.only_inst)  # AttributeError: type object 'E' has no attribute 'only_inst'
```

### 遮蔽（同名覆盖）

查找是“先找到就返回”，所以下层的同名成员会遮蔽上层的：

```python
class B:
  x = "类的x"

b = B()
print(b.x)            # 类的x    ← 实例字典里没有 x，从类上找到
b.x = "实例的x"        # 写入 b.__dict__，不会改动 B.x
print(b.x)            # 实例的x  ← 自身先命中
print(B.x)            # 类的x    ← 类不受影响
print(b.__dict__)     # {'x': '实例的x'}
```

JavaScript 类比（原型链的遮蔽行为完全一致）：

```js
class B {}
B.prototype.x = "原型的x"

const b = new B()
console.log(b.x)                        // 原型的x
b.x = "实例的x"                          // 写到实例自身，不动原型
console.log(b.x)                        // 实例的x
console.log(B.prototype.x)              // 原型的x
console.log(Object.hasOwn(b, "x"))      // true
```

### 例外：数据描述符会插队

上面的顺序有一个例外。定义了 `__set__` 或 `__delete__` 的对象叫**数据描述符**（`property` 就是最常见的一种），它的优先级**高于“自身”**：

```python
class C:
  @property
  def v(self):
    return "property 返回值"

c = C()
c.__dict__["v"] = "实例字典里的v"   # 绕过 property 强行塞进实例字典
print(c.__dict__)                  # {'v': '实例字典里的v'}
print(c.v)                         # property 返回值  ← 类上的 property 赢了
```

类与元类之间同理，元类上的 `property` 会盖住类自己的同名属性：

```python
class Meta2(type):
  @property
  def tag(cls):
    return "元类的property"

class D(metaclass=Meta2):
  tag = "D自己的tag"

print(D.tag)               # 元类的property
print(D.__dict__["tag"])   # D自己的tag  ← 值还在，只是被描述符挡住了
```

所以完整的顺序是：

1. **类型链上的数据描述符**（`property` 等）
2. **自身**（实例的 `__dict__` / 类的 MRO）
3. **类型链上的其他成员**（普通属性、方法、非数据描述符）
4. 都找不到 → 调用 `__getattr__`（如果定义了），否则 `AttributeError`

日常写业务代码只要记住第 2、3 步；第 1 步在你用 `property`、`ORM` 字段、`__slots__` 时才会体现出来。

### 两条查找链的 JavaScript 类比

JS 里同样是两条链，理解了原型链就能对上：

```js
class Base {
  static who = "Base"
}

class A extends Base {
  static aOnly = "只有A有"
}

const a = new A()

// 实例查找：a → A.prototype → Base.prototype → Object.prototype
// 对应 Python：a.__dict__ → type(a).__mro__

// 类自身查找：A → Base → Function.prototype
// 对应 Python：A.__mro__ → 元类的 __mro__
console.log(A.who)                             // Base（沿静态继承链找到）
console.log(Object.getPrototypeOf(A) === Base) // true
console.log(a.aOnly)                           // undefined（静态成员不在实例链上）
```

| Python | JavaScript |
| ------ | ---------- |
| 实例 `a` 的查找链 | `a` → `A.prototype` → 父类 `prototype` → `Object.prototype` |
| 类 `A` 自身的 MRO | `A` → 父类 → `Function.prototype`（静态继承链） |
| 元类 MRO | **无直接对应**（`Function.prototype` 只提供固定的函数能力，不可自定义） |
| 数据描述符插队 | 近似 `Object.defineProperty` 定义的 getter / setter |
| `__getattr__` 兜底 | `Proxy` 的 `get` 拦截 |

> **说明：** 最大差异是 Python 的元类层可以自定义（写一个继承 `type` 的类），JS 没有等价机制，最接近的是 `Proxy` 或 `Object.setPrototypeOf(A, X)`。上一节「类为什么可调用」也是同理：Python 能改元类的 `__call__`，JS 只能用 `Proxy` 的 `construct` 拦截 `new`。
