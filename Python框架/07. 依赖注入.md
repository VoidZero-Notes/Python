## 理解 IoC、DI、IoC 容器

`IoC`：**Inversion of Control，控制反转**

`DI`：**Dependency Injection，依赖注入**

| 概念 | 角色 |
| ---- | ---- |
| IoC | 设计思想：把某种**选择权**移交出去，避免与具体实现耦合 |
| DI | 把 IoC 落地的手段：由外部把依赖传进来 |
| IoC 容器 | 优化 DI 的工具，负责交付依赖项 |

下面用「上传文件」走三遍：硬编码 → 手动注入 → 容器交付。

### 硬编码依赖

`upload_file` 写死调用 `ali_oss_upload`，后者又写死调用 `check_permission`。换云厂商、换成测试假实现，都得改这两个函数。

```python
def check_permission(user: str):
  print(f"验证用户{user}权限")
  return True

def ali_oss_upload(user: str, file: str):
  if not check_permission(user):
    raise Exception("权限不足")
  print(f"阿里云，{file} 上传中...")

def upload_file(user: str, file: str):
  print("上传准备")
  ali_oss_upload(user, file)
  print("上传成功")

# 正常情况
upload_file("张三", "1.txt")

# 特殊情况：希望切换为腾讯云怎么办？？？
# 测试环境：希望使用假的oss上传怎么办？？？
```

### 依赖注入

把 `oss_upload`、`has_permission` 变成参数。调用方决定传哪套实现，被调函数不再自己挑选依赖。

```python
from typing import Callable

def check_permission(user: str) -> bool:
  print(f"验证用户{user}权限")
  return True

def ali_oss_upload(user: str, file: str, has_permission: Callable):
  if not has_permission(user):
    raise Exception("权限不足")
  print(f"阿里云，{file} 上传中...")

def upload_file(user: str, file: str, oss_upload: Callable, has_permission: Callable):
  print("上传准备")
  oss_upload(user, file, has_permission)  # 注意这里传入的是函数本身
  print("上传成功")

# 正常情况
upload_file("张三", "1.txt", ali_oss_upload, check_permission)

# 特殊情况：希望切换为腾讯云怎么办？？？
def tencent_oss_upload(user: str, file: str, has_permission: Callable):
  if not has_permission(user):
    raise Exception("权限不足")
  print(f"腾讯云，{file} 上传中...")

upload_file("张三", "1.txt", tencent_oss_upload, check_permission)

# 测试环境：希望使用假的oss上传怎么办？？？
def fake_upload(user: str, file: str, has_permission: Callable):
  if not has_permission(user):
    raise Exception("权限不足")
  print(f"模拟，{file} 上传中...")

def fake_check_permission(user: str) -> bool:
  print(f"模拟：验证用户{user}权限")
  return True

upload_file("张三", "1.txt", fake_upload, fake_check_permission)
```

### IoC 容器

手动传参在调用链一长就会很烦。用 `Depends` 声明默认依赖，容器负责交付；切换实现时调用 `override`，不必改调用处。

`Depends.py`：

```python
from __future__ import annotations

from collections.abc import Callable
from typing import Any

class Depends:
  _overrides: dict[Callable[..., Any], Callable[..., Any]] = {}

  def __init__(self, func: Callable[..., Any]) -> None:
    self.func = func

  def __call__(self, *args: Any, **kwds: Any) -> Any:
    actual = self._overrides.get(self.func, self.func)
    return actual(*args, **kwds)

  @classmethod
  def override(
    cls,
    original: Callable[..., Any],
    replacement: Callable[..., Any],
  ) -> None:
    cls._overrides[original] = replacement

  @classmethod
  def clear_override(cls, func: Callable[..., Any] | None = None) -> None:
    if func is not None:
      cls._overrides.pop(func, None)
    else:
      cls._overrides.clear()
```

JavaScript 类比：

```js
const overrides = new Map()

const Depends = (func) => {
  return (...args) => {
    const actual = overrides.get(func) ?? func
    return actual(...args)
  }
}

Depends.override = (original, replacement) => {
  overrides.set(original, replacement)
}

Depends.clearOverride = (func) => {
  if (func != null) {
    overrides.delete(func)
  } else {
    overrides.clear()
  }
}
```

> **说明：** Python 的 `Depends` 实例能直接 `obj()`，靠的是 `__call__`。JavaScript 没有这个机制，所以 `Depends(fn)` 返回一个包装函数；调用时再查 `overrides`。`override` / `clearOverride` 挂在 `Depends` 上，对应 Python 的 `@classmethod`。`_overrides` 是类属性、所有实例共享；这里用闭包里的 `Map` 扮演同一角色。

`main.py`：

```python
from Depends import Depends

def check_permission(user: str) -> bool:
  print(f"验证用户{user}权限")
  return True

def ali_oss_upload(user: str, file: str, has_permission=Depends(check_permission)):
  if not has_permission(user):
    raise Exception("权限不足")
  print(f"阿里云，{file} 上传中...")

def upload_file(user: str, file: str, oss_upload=Depends(ali_oss_upload)):
  print("上传准备")
  oss_upload(user, file)  # 注意这里传入的是函数本身
  print("上传成功")

# 正常情况
upload_file("张三", "1.txt")

# 特殊情况：希望切换为腾讯云怎么办？？？
def tencent_oss_upload(user: str, file: str, has_permission=Depends(check_permission)):
  if not has_permission(user):
    raise Exception("权限不足")
  print(f"腾讯云，{file} 上传中...")

Depends.override(ali_oss_upload, tencent_oss_upload)
upload_file("张三", "2.txt")

# 测试环境：希望使用假的oss上传怎么办？？？
def fake_upload(user: str, file: str, has_permission=Depends(check_permission)):
  if not has_permission(user):
    raise Exception("权限不足")
  print(f"模拟，{file} 上传中...")

def fake_check_permission(user: str) -> bool:
  print(f"模拟：验证用户{user}权限")
  return True

Depends.clear_override()
Depends.override(ali_oss_upload, fake_upload)
Depends.override(check_permission, fake_check_permission)
upload_file("张三", "3.txt")
```

JavaScript 类比：

```js
const checkPermission = (user) => {
  console.log(`验证用户${user}权限`)
  return true
}

const aliOssUpload = (user, file, hasPermission = Depends(checkPermission)) => {
  if (!hasPermission(user)) {
    throw new Error("权限不足")
  }
  console.log(`阿里云，${file} 上传中...`)
}

const uploadFile = (user, file, ossUpload = Depends(aliOssUpload)) => {
  console.log("上传准备")
  ossUpload(user, file)
  console.log("上传成功")
}

// 正常情况
uploadFile("张三", "1.txt")

// 特殊情况：希望切换为腾讯云怎么办？？？
const tencentOssUpload = (user, file, hasPermission = Depends(checkPermission)) => {
  if (!hasPermission(user)) {
    throw new Error("权限不足")
  }
  console.log(`腾讯云，${file} 上传中...`)
}

Depends.override(aliOssUpload, tencentOssUpload)
uploadFile("张三", "2.txt")

// 测试环境：希望使用假的oss上传怎么办？？？
const fakeUpload = (user, file, hasPermission = Depends(checkPermission)) => {
  if (!hasPermission(user)) {
    throw new Error("权限不足")
  }
  console.log(`模拟，${file} 上传中...`)
}

const fakeCheckPermission = (user) => {
  console.log(`模拟：验证用户${user}权限`)
  return true
}

Depends.clearOverride()
Depends.override(aliOssUpload, fakeUpload)
Depends.override(checkPermission, fakeCheckPermission)
uploadFile("张三", "3.txt")
```

> **说明：** Python 默认参数只在**定义函数时求值一次**；JavaScript 默认参数在**每次缺参调用时都会再求值**。对本例无影响：包装函数每次调用都按当前 `overrides` 解析。
