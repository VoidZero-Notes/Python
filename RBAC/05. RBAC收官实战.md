## 项目准备和启动

在RBAC模块的前四讲中，我们完成了从“问题认知”到“方案设计”的全过程，相当于是完成了造房子的设计图纸。

**本讲的目标：把这栋“房子”真正盖起来，让你能走进去、推开门、试试门禁好不好用。** 我们不深入讲解细节（那是后续Java专题课的内容），而是让你亲手启动这个系统，感受它运行起来的样子。

### 技术栈

- Spring Boot
- Spring Security
- JPA / Hibernate

- JWT (jjwt)
- Java

### 快速开始

#### 准备 PostgreSQL 数据库

```sql
CREATE DATABASE rbac_demo;
```

确保 `application.yml` 中的连接信息与你的 PostgreSQL 配置一致：

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/rbac_demo
    username: postgres
    password: 123456
```

#### 构建与运行

```bash
# 编译打包
mvn clean package -DskipTests

# 运行
java -jar target/rbac-demo-1.0.0.jar
```

或直接用 Maven 运行：

```bash
mvn spring-boot:run
```

Flyway 会在启动时自动创建表结构并插入种子数据。

### 数据库表结构

- **users** - 用户表
- **roles** - 角色表
- **permissions** - 权限表
- **user_roles** - 用户-角色关联表
- **role_permissions** - 角色-权限关联表
- **articles** - 文章表

### 权限模型

```
User → UserRole → Role → RolePermission → Permission (resource:action)
```

用户通过角色间接关联权限，实现标准的 RBAC 模型。

## Postman测试流程

### 测试账号

项目中预置了三个测试账号，分别对应不同的角色：

| 用户名   | 密码       | 角色   | 权限范围               |
| -------- | ---------- | ------ | ---------------------- |
| `admin`  | `admin123` | 管理员 | 所有权限               |
| `editor` | `admin123` | 编辑   | 文章增删改查（自己的） |
| `viewer` | `admin123` | 访客   | 仅文章阅读             |

> [!WARNING]
> **这些账号和密码仅用于学习和测试目的。** 在实际生产环境中，请使用强密码策略。

### 第一步：配置Postman环境变量

**为什么需要环境变量？**

在测试过程中，我们需要反复使用`base_url`和`token`。把它们定义为环境变量，可以避免在每个请求中重复填写。

**操作步骤**：

1. 在Postman中点击左侧的 **Environments**（环境）
2. 点击 **+** 创建一个新环境，命名为 `RBAC Dev`
3. 添加以下变量：

| 变量名     | 初始值                  | 当前值                  | 说明                    |
| ---------- | ----------------------- | ----------------------- | ----------------------- |
| `base_url` | `http://localhost:8080` | `http://localhost:8080` | 服务器地址              |
| `token`    | （留空）                | （自动填充）            | JWT令牌，登录后自动设置 |

4. 点击 **Save** 保存环境
5. 在Postman右上角的下拉菜单中选择 **RBAC Dev** 环境

### 第二步：登录接口——获取JWT Token

**请求配置**：

| 配置项  | 值                               |
| ------- | -------------------------------- |
| Method  | `POST`                           |
| URL     | `{{base_url}}/api/auth/login`    |
| Headers | `Content-Type: application/json` |
| Body    | 见下方                           |

**请求体（JSON）** ：

```json
{
  "username": "editor",
  "password": "admin123"
}
```

**操作步骤**：

1. 在Postman中新建一个请求
2. 按上述配置填写
3. 点击 **Send**

**预期响应**：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "username": "admin",
    "authorities": ["article:create", "article:read", "article:update"]
  }
}
```

### 第三步：配置认证请求头

所有需要认证的接口都需要在请求头中携带JWT Token。

**配置方式**：

1. 在Postman的 **Authorization** 选项卡中
2. Type选择 **Bearer Token**
3. Token输入 `{{token}}`

> [!NOTE]
> 使用`{{token}}`变量后，Postman会自动从环境变量中读取token值填入请求头。这样你不需要在每个请求中手动复制粘贴token。

### 第四步：测试不同角色的权限

现在我们可以用三个不同的账号登录，测试它们对各个API接口的访问权限。

## 常见问题排查

### 启动失败：数据库连接错误

**错误信息**：

```
Caused by: org.postgresql.util.PSQLException: Connection refused
```

**原因**：PostgreSQL未启动，或`application.yml`中的连接配置不正确。

**解决方案**：

1. 确认PostgreSQL已启动：`psql -U postgres`
2. 检查`application.yml`中的`url`、`username`、`password`是否正确
3. 确认数据库`rbac_demo`已创建

### 启动失败：表已存在

**错误信息**：

```
Migration V1__create_tables.sql failed: relation "users" already exists
```

**原因**：数据库中已有同名表，但Flyway的版本记录不匹配。

**解决方案**：

1. 删除数据库重新创建：`DROP DATABASE rbac_demo; CREATE DATABASE rbac_demo;`
2. 或执行：`mvn flyway:clean` 清理后重新启动

### 请求返回401 Unauthorized

**原因**：请求未携带有效的JWT Token。

**解决方案**：

1. 确认已调用登录接口并获取了token
2. 确认请求头中包含`Authorization: Bearer <token>`
3. 确认Postman环境变量`{{token}}`已正确设置

### 请求返回403 Forbidden

**原因**：用户已认证但没有执行该操作的权限。

**解决方案**：

1. 确认当前登录的用户角色是否正确
2. 确认该角色是否拥有请求所需的权限
3. 查看数据库中的`role_permissions`表，确认权限配置

### 端口被占用

**错误信息**：

```
Port 8080 was already in use
```

**原因**：另一个应用正在使用8080端口。

**解决方案**：

1. 关闭占用8080端口的其他应用
2. 或在`application.yml`中修改端口：`server.port: 8081`
